# API Documentation

Base URL (local): `http://localhost:8000/api`
Interactive OpenAPI docs (auto-generated by FastAPI): `http://localhost:8000/docs`

## `GET /health`
Returns service status, today's simulated date, and the current forecast cache
size.

## `GET /skus`
Returns all 6 SKUs with criticality, cost, and margin fields.

## `GET /dcs`
Returns all 5 DCs with type, capacity, and supplier lead time.

## `GET /scenarios`
Returns the list of deliberately engineered demo scenario anchors (SKU/DC pairs
and their expected behavior), for quick navigation in the demo.

## `GET /forecast/{sku_id}/{dc_id}`
Returns baseline vs. sensed forecast, sensing multiplier + explanation, holdout
evaluation metrics (MAE/RMSE/MAPE) for both, and a comparison note.
`422` if `sku_id` or `dc_id` is not recognized.

## `GET /inventory/{sku_id}/{dc_id}`
Returns current stock, batch list with days-to-expiry, days of supply, DC
capacity headroom, and the FEFO allocation / expiry-risk breakdown.

## `GET /recommendation/{sku_id}/{dc_id}`
The full decision payload: forecast, inventory, FEFO, ROP, risk scores, root
causes, network alternatives, cost of inaction, priority, and the final
decision (action/quantity/source/timing/explanation). This is what powers
Screen 2 in full.

## `GET /network/{sku_id}/{dc_id}`
Just the network-alternatives search for this SKU/DC (subset of what
`/recommendation` returns, useful for isolated inspection).

## `POST /what-if`
Body:
```json
{
  "sku_id": "MED-004",
  "dc_id": "DC-METRO-MUM",
  "demand_change_pct": 60,
  "flu_active": true,
  "lead_time_delta": 3,
  "cost_weight_stockout": 1.5
}
```
All fields except `sku_id`/`dc_id` are optional. Validated ranges:
`demand_change_pct` ∈ [-90, 300], `lead_time_delta` ∈ [-10, 30],
`cost_weight_stockout` ∈ [0.1, 5.0]. Returns `before` (current state, from
cache) and `after` (live recompute with the override applied), plus
`compute_time_ms`.

## `GET /network-map`
Returns `nodes` (one per DC, with computed state: Healthy / Excess / Shortage)
and `edges` (one per SKU currently recommended for TRANSFER, with quantity and
timing) — this is exactly what the Screen 1 risk map renders, with no
decorative edges added client-side.

## `GET /attention-queue?limit=10`
Returns the SKU × DC combinations that are not simply MONITOR-with-low-risk,
sorted by priority score descending.

## `GET /network-health`
Aggregate metrics across all 30 SKU × DC combinations: network health score,
average stockout/expiry risk, action distribution, total cost-of-inaction
exposure, and critical-priority count.

## `GET /monitoring/metrics`
Average sensed-forecast MAPE and MAE across all combinations.

## `GET /monitoring/history`
Recorded monitoring snapshots (auto-seeded with the current computed state on
first call if no history exists yet).

## Error handling

- Unknown `sku_id`/`dc_id` → `422` with a detail message listing valid values.
- Malformed `what-if` payload (out-of-range values) → `422` from Pydantic
  validation, with field-level detail.
- All other unexpected errors surface as `500` rather than crashing the
  server process (FastAPI's default exception handling).
